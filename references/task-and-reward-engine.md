# 每日任务、有效出勤与奖励引擎

本文件定义“获取任务 → 接取锁定 → 作答提交 → 验证入账 → 查看结算”的唯一日循环。处理今日任务、签到、提交、查看结算、补记、复归或调整点时必须完整读取本文件；任何写入同时遵守 [state-schema.md](state-schema.md)。

## 1. 日循环与状态机

只运行以下主循环：

```text
获取任务 → 接取并锁定 → 作答 → 提交证据 → 验证并入账 → 查看结算
```

`daily_quest.status` 只按下列状态移动：

```text
not_generated → offered → accepted → submitted → verified → reward_ready → revealed
```

允许的回退只有：证据不足时从 `submitted` 回到 `accepted`。保留提交引用和缺口说明，不发奖励、不记有效出勤。不要跳过 accepted 后再补写门槛。

验证成功时在同一事务内短暂经过 `verified` 并到达 `reward_ready`。查看结算只把结算单改为已展示并将 daily quest 置为 `revealed`，不再次改变学习记录。

“今日首胜”由当天首次有效出勤的验证入账触发，不由“查看结算”按钮触发。查看结算只负责展示，不负责入账。

## 2. 任务获取与三选一

默认使用 `pull`：用户说“今日任务”或“开始学习”时生成。仅在用户明确同意、平台支持可靠定时触发且配置了时间时使用 `push`；失败时退回 pull，不假装已发送。

每天按用户时区只生成一个 `offer_id`。重复请求时重显同一组任务，不重新抽池。每组必须提供恰好三个互斥选项，并且每项都能在当天可投入时间内完成：

- A 学新技能：接触一项高价值技能。
- B 提战绩：围绕一个行测模块完成可记录正确率与实际用时的练习。
- C 改错：处理已到期错题或高复发易错点。

若某类没有合法候选，仍保持 A/B/C 的三个位置，但用另一类候选替代并准确标记其真实类型；不得编造不存在的复习或易错点。

每个选项在展示前保存完整对象：

```json
{
  "task_id": "YYYY-MM-DD-A-v1",
  "offer_id": "offer:YYYY-MM-DD",
  "campaign_id": "当前备考周期ID",
  "season_id": "当前赛季ID",
  "option_version": 1,
  "type": "open|evolve|hunt|review|ranked",
  "skill_ids": ["skill-01 至 skill-70 中的稳定 ID"],
  "subject": "行测|申论",
  "module": "模块或题型",
  "duration_minutes": 25,
  "objective": "唯一能力目标",
  "content": "可直接执行的具体任务",
  "source": "题目、材料或平台来源",
  "evidence_required": ["答案", "用时", "订正或方法说明"],
  "attendance_gate": "有效出勤的最低证据",
  "performance_gate": "题量、正确率和实际用时要求",
  "reward_preview": "达标后可能变化的技能、错题、易错点、战绩或勋章",
  "medal_targets": ["至少一枚尚未点亮的固定勋章ID"],
  "ranked": false,
  "rank_gate": null,
  "strong_pass_gate": null,
  "candidate_score": 0
}
```

规则 1.6 下，A、B、C 三个候选都必须推进至少一枚未点亮勋章。行测模块训练关联正确率与用时勋章，订正关联纠错勋章，模考关联战绩或赛季勋章。勋章全部点亮后才允许 `medal_targets` 为空。勋章关联不改变到期风险和提分价值的优先级。

`open` 和 `evolve` 任务必须用 `skill_ids` 引用固定的 `skill-01` 至 `skill-70`。自然语言名称只用于展示；找不到对应 ID 时停止生成该候选，不得创建同义技能或自定义 ID。

没有可靠题源时，要求用户提供题目或调用已安装内容 Skill。不得只给“刷 20 道资料分析”这种无法验收的空任务；必须锁定范围、来源或待用户粘贴的输入方式。

## 3. 任务排序算法

先生成合法候选，再给每个候选的五项因素归一到 0–1，计算：

```text
candidate_score =
  35 × 到期风险
+ 30 × 提分杠杆
+ 20 × 临门一脚
+ 10 × 新鲜度
+  5 × 用户偏好
```

- 到期风险：已过复测日期、错误复发或保持等级将失效时提高。
- 提分杠杆：核心模块短板、目标分差和真题频率越高越高。
- 临门一脚：距离下一枚量化勋章或易错点复测通过只差一步时提高。
- 新鲜度：近期任务重复越少越高；不得用它压过到期核心任务。
- 用户偏好：只用于同价值候选排序，不允许回避核心短板。

选择规则：

1. 若有到期复测或高风险易错点，三项中至少包含一项。
2. 三项尽量覆盖“新能力、巩固、纠错”三种心理体验，避免同质化。
3. 核心技能优先于扩展技能；冲刺期禁止低收益新技能挤占复测。
4. 最近两次失败后降低单次任务跨度，不降低已经公布的勋章门槛；把任务拆小并保留再次挑战路径。
5. 最近连续三次轻松通过时提高材料复杂度、时间压力或迁移性，不靠单纯加题量制造难度。

没有足够数据计算某项时赋 0，并在内部记录“未知”；不得凭感觉伪造小数精度。分数用于稳定排序，不作为向用户展示的能力评分。

## 4. 接取、重掷与锁定

用户回复 A/B/C 时：

1. 确认选项来自当天 `offer_id`。
2. 复制所选任务的全部条件到 `locked_conditions`。
3. 保存 `accepted_task_id`、接取时间和幂等事件。
4. 只展示已锁定任务及提交格式，留下“完成后提交证据”一个动作。

用户未明确回复字母但直接对某项开始作答时，把首次无歧义作答视为接取。无法判断对应选项时先询问，不擅自选择。

每天最多更换一个尚未接取的选项一次：季前校准免费；正式赛季消耗 2 调整点。只替换被指定的那个选项，保留 offer ID，把该位置的 `option_version` 加 1，并生成新的 task ID。接取后不得更换；用户始终可以从其余原选项中选择。

锁定后不得修改题目范围、题量、时限、出勤门槛、勋章门槛、保底线、目标线、冲刺线或奖励。发现题目或答案本身有错误时把本任务标记为 `void`，退还本任务已消费资源，保留真实学习记录但不做勋章或段位判定，再生成替代任务。

## 5. 证据与有效出勤

把有效出勤定义为“当天留下达到事前最低行动的实力记录”。每天最多一次；同日继续训练可以增加能力证据，但不重复每日首胜。

默认最低行动满足任一项：

- 至少 5 道行测题，含逐题答案、总用时，以及错题订正或方法说明。
- 1 道事前声明的高难题，含完整推理和至少 1 个同类验证。
- 1 个到期易错点，含错误原因、纠正策略和同类复测。
- 1 个申论微输出或完整小题，按事前量表核验并保留原文。
- 1 次到期能力复测，含题目范围、答案、用时和结果。
- 当天任务事先标明的最低有效部分及其可复查产物。

只看课、阅读、抄答案、挂机、纯计时或口头声称完成默认不计。若任务事前要求结构化检索、闭卷复述或应用练习，并且用户提交产物，才按锁定门槛判定。

出勤状态：

- `effective`：证据完整并达到最低行动。
- `started`：已开始但尚缺最低证据。
- `planned_rest`：计划休整；不视为缺席。
- `missed`：计划学习日结束仍无有效证据。
- `recovery`：连续漏掉两个计划学习日后完成复归任务。

任务未达到勋章门槛，但真实作答和实质订正达到 attendance gate 时，仍记 `effective`；只发每日首胜，保留练习、错题和易错点进度，不点亮勋章或改变段位。

### 5.1 行测练习战绩

行测练习提交如果同时包含题量、正确数和实际总用时，创建唯一 `practice_records[]`。不得把计划时长当作实际用时，也不得从正确率反推缺失题量。记录至少包含：

```json
{
  "practice_id": "稳定ID",
  "campaign_id": "当前备考周期ID",
  "season_id": "当前赛季ID",
  "task_id": "对应任务",
  "submission_ref": "原始提交引用",
  "date": "YYYY-MM-DD",
  "subject": "行测",
  "module": "五个行测模块之一",
  "question_count": 10,
  "correct_count": 8,
  "accuracy_rate": 80.0,
  "duration_seconds": 800,
  "seconds_per_question": 80.0,
  "source": "题源",
  "locked_before_start": true,
  "ruleset_version": "1.6.0"
}
```

`accuracy_rate = correct_count / question_count × 100`，`seconds_per_question = duration_seconds / question_count`，均保留两位小数。只有作答前已锁定且单次不少于 10 题的记录可以点亮模块量化勋章；未锁定或不足 10 题的完整数据仍可作为普通练习战绩展示。同一任务、提交引用和模块只能有一条记录。

用“有效出勤数 ÷ 计划学习日数”作为节奏指标。effective 令 `momentum_level` 加 1，最高 3；missed 减 1，最低 0；planned_rest 不变。连续天数只作辅助展示，不因中断清空永久记录。

## 6. 提交验收

收到“提交作业”后先把原始消息、附件或平台记录保存为稳定 `submission_ref`，再按锁定条件验收：

1. 核对任务 ID、题目范围、答案来源和时间口径。
2. 提取答案、正确率、用时、未作答、订正、解释、申论原文和评分来源。
3. 标记无法核验的字段；不把缺失值当作 0 或失败。
4. 分别判定：`task_result`、`attendance_result`、`practice_result`、`medal_result`、`error_hunt_result`、`rank_result`。
5. 若 attendance 所需证据不完整，返回唯一最小缺口并回到 accepted；不结算。
6. 若最低证据完整，进入原子结算。勋章或段位即使没有变化，也必须如实保存练习和战绩。

同一份证据不得同时被拆成多次每日首胜。可以让同一证据支持多个相关能力判断，但必须逐项满足各自锁定门槛并引用同一 submission ref。

申论评分必须保存来源：官方/机构批改、教师批改、平台量表、用户自评或 AI 内部估分。评分同时保存原始分数 `score`、满分 `score_max` 和确定计算的 `score_rate`；评分前先锁定满分和量表，不能只写一个无法判断口径的百分数字。AI 内部估分只更新维度反馈，不能独立触发稳定通关或改变段位。只要提交中包含实质申论作答，`pass`、`partial` 和 `fail` 都必须保存原文并同步写入申论答题册。

每日申论小题、公文题或大作文练习只进入申论答题册和对应技能证据，不写入 `assessments`。只有完整考试、完整模考或事前锁定的模块测试才写入战绩；其中申论完整成绩仍须满足可比评分来源，才能用于定级。

## 7. 原子结算与结算单

一次验证事务按顺序计算，但只通过 `scripts/state_store.py commit` 写入一次：

1. 检查验证 event ID 与 task/reward 唯一约束。
2. 写入原始证据引用和五类判定。
3. 更新有效出勤、练习战绩、错题、易错点、勋章、排位战绩与段位；申论提交同时创建或更新唯一 `portfolio:<submission_ref>`。
4. 生成唯一 `reward_id = reward:<task_id>`。
5. 更新调整点与流水，应用上限。
6. 创建 `status = unrevealed` 的结算单。
7. 在申论验证结果中写入 `portfolio_changes`，把任务置为 `reward_ready` 并原子保存。

已验证申论任务如果没有对应答题册条目，状态工具必须拒绝整次提交。重复验证同一个 `submission_ref` 时更新原条目，不得重复创建。

结算单至少包含：

```json
{
  "reward_id": "reward:<task_id>",
  "campaign_id": "当前备考周期ID",
  "season_id": "当前赛季ID",
  "date": "YYYY-MM-DD",
  "task_id": "对应任务",
  "submission_refs": [],
  "task_result": "pass|partial|fail|void",
  "attendance_awarded": false,
  "ability_changes": [],
  "error_hunt_changes": [],
  "ranked": false,
  "rank_delta": 0,
  "command_points_delta": 0,
  "set_progress": [],
  "status": "unrevealed",
  "created_at": null,
  "revealed_at": null
}
```

保存失败时不得提示“结算已入账”。重复验证同一 submission ref 时返回已有结算单的当前状态，不重新计算。

## 8. 奖励规则与调整点

奖励按五层表达，但全部来自真实事实：

1. 任务结果：练习战绩、技能证据、错题订正、易错点和勋章进度。
2. 每日首胜：当天首次 effective 时点亮学习日历、更新节奏并获得 1 调整点。
3. 段位结果：只有 ranked 战绩进入滚动窗口，并按锁定三条线重算段位与三星；不直接奖励星数。
4. 模块奖励：只更新赛季开始时锁定的模块目标与勋章条件。
5. 周/赛季奖励：事实战报、永久勋章和预先锁定的称号。

调整点默认上限 6，只允许：

- 2 点：每天更换一个未接取选项一次。
- 1 点：把一次到期复习顺延不超过 24 小时。
- 3 点：指定下一计划学习日三选一中的主模块。

调整点不能购买有效出勤、分数、勋章、段位或星级，也不能改已锁定门槛。每日首胜最多增加 1 点；赛季挑战通过后最多增加 2 点，仍受上限约束。任何获得、使用、退还或因上限溢出的数量都写入 transaction。

勋章与称号目录在赛季开始前锁定。允许使用确定性称号与视觉文案，禁止随机抽取具有能力意义的奖励，禁止任务结束后临时创造“限定稀有勋章”。

## 9. 查看结算与补记

查看结算时只读取 `unrevealed` 结算单，按创建时间依次展示，然后写入 `revealed_at`。重复发送“查看结算”时展示“本结算单已查看”及原结果，不再改变任何学习记录。

忘记查看不会丢失结果。新一天第一次交互时先自动展示旧结算单，再处理今日任务；旧结算与今日新事件分别记录，避免混账。

默认按证据提交当天记录。只有带原始日期的做题平台记录、批改记录、文件时间或其他可复查材料才允许补记历史 effective。补记不能补发已经被后续周期结算消费的随机或时效奖励；可以修正事实统计，并在受影响周报中标记“补记后修订”。不得凭回忆补签。

## 10. 中断与复归

连续漏掉两个计划学习日后，暂停普通三选一，只发 5–15 分钟复归任务。复归任务仍要求实力产物，例如 5 题带订正、一个到期易错点复测或一个申论提纲；“打开系统”不算复归。

完成后把当天出勤状态记为 `recovery`，同时写 `counts_as_effective = true`；每日首胜照常只发一次，下一计划学习日恢复三选一。不要同时写第二条 `effective` 记录，不要追债式补做所有漏掉任务，不清空连续之外的任何永久记录。

计划外精力不足时允许在接取前选择较短选项；接取后若客观中断，日期切换时把任务以 `started` 归档，下一日重新生成任务，不把未完成部分伪装成通过。午夜后补交昨日证据时按“补记”处理，必须引用原任务、原始完成日期和可复查材料，不把它并入今日任务。

## 11. 固定输出模板

### 发任务

```text
【今日战场】
赛季 / 第几天 / 本周有效出勤 / 综合段位 / 调整点

【A 学新技能】时间｜目标｜任务｜证据｜出勤门槛｜战绩门槛｜可能变化
【B 提战绩】时间｜目标｜任务｜证据｜出勤门槛｜战绩门槛｜可能变化
【C 改错】时间｜目标｜任务｜证据｜出勤门槛｜战绩门槛｜可能变化

【下一动作】
回复 A、B 或 C。
```

### 接取成功

```text
【任务已锁定】
任务 / 时间 / 来源 / 提交内容
有效出勤门槛 / 练习战绩与勋章门槛 / 是否进入段位窗口 / 达标后变化

【下一动作】
完成后按给定格式提交证据。
```

### 证据不足

```text
【尚未结算】
已收到：可核验内容
唯一缺口：补充内容
当前状态：started；尚未签到、记录练习战绩、点亮勋章或改变段位

【下一动作】
只补交上述缺口。
```

### 验证完成

```text
【验证完成】
任务：
有效证据：
判定：任务 / 有效出勤 / 练习战绩与勋章 / 错题与易错点 / 排位战绩与段位

【结算单·待查看】
结果已安全入账。回复“查看结算”展示详情。
```

### 查看结算

```text
【每日首胜】
有效出勤与依据；本周有效 / 计划；当前节奏

【练习战绩与勋章】
题量、正确数、正确率、实际总用时、平均每题用时，以及点亮或尚未达到的勋章

【易错点】
待确认、已找到原因、纠正中、已解决，或无变化

【段位结算】
新增战绩、滚动窗口、当前段位与距下一段差值；非 ranked 明确写“不影响段位”

【资源】
```

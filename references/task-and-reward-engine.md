# 每日任务、有效出勤与奖励引擎

本文件定义“获取任务 → 接取锁定 → 作答提交 → 验证入账 → 领取揭晓”的唯一日循环。处理今日任务、签到、提交、领取、补记、复归或指挥点时必须完整读取本文件；任何写入同时遵守 [state-schema.md](state-schema.md)。

## 1. 日循环与状态机

只运行以下主循环：

```text
获取任务 → 接取并锁定 → 作答 → 提交证据 → 验证并入账 → 领取并揭晓
```

`daily_quest.status` 只按下列状态移动：

```text
not_generated → offered → accepted → submitted → verified → reward_ready → revealed
```

允许的回退只有：证据不足时从 `submitted` 回到 `accepted`。保留提交引用和缺口说明，不发奖励、不记有效出勤。不要跳过 accepted 后再补写门槛。

验证成功时在同一事务内短暂经过 `verified` 并到达 `reward_ready`。领取只把奖励改为已展示并将 daily quest 置为 `revealed`，不再次改变资产。

“今日首胜”由当天首次有效出勤的验证入账触发，不由领取按钮触发。领取是仪式，不是账本。

## 2. 任务获取与三选一

默认使用 `pull`：用户说“今日任务”或“开始学习”时生成。仅在用户明确同意、平台支持可靠定时触发且配置了时间时使用 `push`；失败时退回 pull，不假装已发送。

每天按用户时区只生成一个 `offer_id`。重复请求时重显同一组任务，不重新抽池。每组必须提供恰好三个互斥选项，并且每项都能在当天可投入时间内完成：

- A 开图：接触一张高价值新能力卡。
- B 进化：补齐一张已发现或已拥有卡片的下一形态。
- C 追猎：处理已到期或高复发的具体错因。

若某类没有合法候选，仍保持 A/B/C 的三个位置，但用另一类候选替代并准确标记其真实类型；不得编造不存在的复习或错因。

每个选项在展示前保存完整对象：

```json
{
  "task_id": "YYYY-MM-DD-A-v1",
  "offer_id": "offer:YYYY-MM-DD",
  "campaign_id": "当前备考周期ID",
  "season_id": "当前赛季ID",
  "option_version": 1,
  "type": "open|evolve|hunt|review|ranked",
  "subject": "行测|申论",
  "module": "模块或题型",
  "duration_minutes": 25,
  "objective": "唯一能力目标",
  "content": "可直接执行的具体任务",
  "source": "题目、材料或平台来源",
  "evidence_required": ["答案", "用时", "订正或方法说明"],
  "attendance_gate": "有效出勤的最低证据",
  "ability_gate": "发卡或进化门槛",
  "reward_preview": "达标后确定获得的已锁定资产",
  "ranked": false,
  "rank_gate": null,
  "strong_pass_gate": null,
  "candidate_score": 0
}
```

没有可靠题源时，要求用户提供题目或调用已安装内容 Skill。不得只给“刷 20 道资料分析”这种无法验收的空任务；必须锁定范围、来源或待用户粘贴的输入方式。

## 3. 任务排序算法

先生成合法候选，再给每个候选的五项因素归一到 0–1，计算：

```text
candidate_score =
  35 × 到期风险
+ 30 × 提分杠杆
+ 20 × 临门一脚
+ 10 × 新鲜度
+  5 × 用户偏好
```

- 到期风险：已过复测日期、错误复发或保持形态将失效时提高。
- 提分杠杆：核心模块短板、目标分差和真题频率越高越高。
- 临门一脚：距离已锁定卡片、形态或套组只差一步时提高。
- 新鲜度：近期任务重复越少越高；不得用它压过到期核心任务。
- 用户偏好：只用于同价值候选排序，不允许回避核心短板。

选择规则：

1. 若有到期复测或高风险错因，三项中至少包含一项。
2. 三项尽量覆盖“新能力、巩固、纠错”三种心理体验，避免同质化。
3. 核心卡候选优先于扩展收藏；冲刺期禁止低收益开图挤占复测。
4. 最近两次失败后降低单次任务跨度，不降低能力门槛；把任务拆小并保留反杀路径。
5. 最近连续三次轻松通过时提高材料复杂度、时间压力或迁移性，不靠单纯加题量制造难度。

没有足够数据计算某项时赋 0，并在内部记录“未知”；不得凭感觉伪造小数精度。分数用于稳定排序，不作为向用户展示的能力评分。

## 4. 接取、重掷与锁定

用户回复 A/B/C 时：

1. 确认选项来自当天 `offer_id`。
2. 复制所选任务的全部条件到 `locked_conditions`。
3. 保存 `accepted_task_id`、接取时间和幂等事件。
4. 只展示已锁定任务及提交格式，留下“完成后提交证据”一个动作。

用户未明确回复字母但直接对某项开始作答时，把首次无歧义作答视为接取。无法判断对应选项时先询问，不擅自选择。

每天最多重掷一个尚未接取的选项一次：季前校准免费；正式赛季消耗 2 指挥点。只替换被指定的那个选项，保留 offer ID，把该位置的 `option_version` 加 1，并生成新的 task ID。接取后不得重掷；用户始终可以从其余原选项中选择。

锁定后不得修改题目范围、用时、出勤门槛、能力门槛、排位线、强通关线或奖励。发现题目/答案本身有错误时把本任务标记为 `void`，退还本任务已消费资源，保留真实学习记录但不做能力或排位判定，再生成替代任务。

## 5. 证据与有效出勤

把有效出勤定义为“当天留下达到事前最低行动的实力记录”。每天最多一次；同日继续训练可以增加能力证据，但不重复每日首胜。

默认最低行动满足任一项：

- 至少 5 道行测题，含逐题答案、总用时，以及错题订正或方法说明。
- 1 道事前声明的高难题，含完整推理和至少 1 个同类验证。
- 1 个到期错因，含原错因解释、纠正策略和同类复测。
- 1 个申论微输出或完整小题，按事前量表核验并保留原文。
- 1 次到期能力复测，含题目范围、答案、用时和结果。
- 当天任务事先标明的最低有效部分及其可复查产物。

只看课、阅读、抄答案、挂机、纯计时或口头声称完成默认不计。若任务事前要求结构化检索、闭卷复述或应用练习，并且用户提交产物，才按锁定门槛判定。

出勤状态：

- `effective`：证据完整并达到最低行动。
- `started`：已开始但尚缺最低证据。
- `planned_rest`：计划休整；不视为缺席。
- `missed`：计划学习日结束仍无有效证据。
- `recovery`：连续漏掉两个计划学习日后完成复归任务。

任务能力门槛未过，但真实作答和实质订正达到 attendance gate 时，仍记 `effective`；只发每日首胜、保留练习和错因进度，不发能力资产或排位星。

用“有效出勤数 ÷ 计划学习日数”作为节奏指标。effective 令 `momentum_level` 加 1，最高 3；missed 减 1，最低 0；planned_rest 不变。连续天数只作辅助展示，不因中断清空永久资产。

## 6. 提交验收

收到“提交作业”后先把原始消息、附件或平台记录保存为稳定 `submission_ref`，再按锁定条件验收：

1. 核对任务 ID、题目范围、答案来源和时间口径。
2. 提取答案、正确率、用时、未作答、订正、解释、申论原文和评分来源。
3. 标记无法核验的字段；不把缺失值当作 0 或失败。
4. 分别判定：`task_result`、`attendance_result`、`ability_result`、`error_hunt_result`、`rank_result`。
5. 若 attendance 所需证据不完整，返回唯一最小缺口并回到 accepted；不结算。
6. 若最低证据完整，进入原子结算。能力或排位即使失败也必须如实入账练习事实。

同一份证据不得同时被拆成多次每日首胜。可以让同一证据支持多个相关能力判断，但必须逐项满足各自锁定门槛并引用同一 submission ref。

申论评分必须保存来源：官方/机构批改、教师批改、平台量表、用户自评或 AI 内部估分。AI 内部估分只更新维度反馈，不能独立触发稳定通关或掉星。

## 7. 原子结算与奖励包

一次验证事务按顺序计算，但只通过 `scripts/state_store.py commit` 写入一次：

1. 检查验证 event ID 与 task/reward 唯一约束。
2. 写入原始证据引用和五类判定。
3. 更新有效出勤、能力卡、错因、测评与排位。
4. 生成唯一 `reward_id = reward:<task_id>`。
5. 更新指挥点与经济流水，应用上限。
6. 创建 `status = unrevealed` 的奖励包。
7. 把任务置为 `reward_ready` 并原子保存。

奖励包至少包含：

```json
{
  "reward_id": "reward:<task_id>",
  "campaign_id": "当前备考周期ID",
  "season_id": "当前赛季ID",
  "date": "YYYY-MM-DD",
  "task_id": "对应任务",
  "submission_refs": [],
  "task_result": "pass|partial|fail|void",
  "attendance_awarded": false,
  "ability_changes": [],
  "error_hunt_changes": [],
  "ranked": false,
  "rank_delta": 0,
  "command_points_delta": 0,
  "set_progress": [],
  "status": "unrevealed",
  "created_at": null,
  "revealed_at": null
}
```

保存失败时不得提示“奖励已入账”。重复验证同一 submission ref 时返回已有奖励包的当前状态，不重新计算。

## 8. 奖励经济与指挥点

奖励按五层表达，但全部来自真实事实：

1. 任务奖励：能力证据、卡片/形态变化、错因追猎进度。
2. 每日首胜：当天首次 effective 时点亮赛季日历、更新节奏并获得 1 指挥点。
3. 排位奖励：仅 ranked 任务按锁定规则增减星。
4. 套组奖励：只更新赛季开始时锁定的套组与称号。
5. 周/赛季奖励：事实战报、永久奖杯和预先锁定的称号。

指挥点默认上限 6，只允许：

- 2 点：每天重掷一个未接取选项一次。
- 1 点：把一次到期复习顺延不超过 24 小时。
- 3 点：指定下一计划学习日三选一中的主模块。

指挥点不能购买有效出勤、分数、能力卡、形态或星级，不能跳过延迟复测，也不能改已锁定门槛。每日首胜最多发 1 点；赛季 Boss 通过后最多加 2 点，仍受上限约束。任何收入、消费、退还或因上限溢出的点数都写入 transaction。

奖励目录在赛季开始前锁定。允许使用确定性称号与视觉文案，禁止随机抽取具有能力意义的奖励，禁止任务结束后临时创造“限定稀有掉落”。

## 9. 领取与补记

领取时只读取 `unrevealed` 奖励包，按创建时间依次展示，然后写入 `revealed_at`。重复发送“领取”时展示“本奖励已领取”及原结果，不再改变任何资产。

忘记领取不会丢失奖励。新一天第一次交互时先自动揭晓旧奖励，再处理今日任务；揭晓与今日新事件分别记录，避免混账。

默认按证据提交当天记录。只有带原始日期的做题平台记录、批改记录、文件时间或其他可复查材料才允许补记历史 effective。补记不能补发已经被后续周期结算消费的随机或时效奖励；可以修正事实统计，并在受影响周报中标记“补记后修订”。不得凭回忆补签。

## 10. 中断与复归

连续漏掉两个计划学习日后，暂停普通三选一，只发 5–15 分钟复归任务。复归任务仍要求实力产物，例如 5 题带订正、一个到期错因复测或一个申论提纲；“打开系统”不算复归。

完成后把当天出勤状态记为 `recovery`，同时写 `counts_as_effective = true`；每日首胜照常只发一次，下一计划学习日恢复三选一。不要同时写第二条 `effective` 记录，不要追债式补做所有漏掉任务，不清空连续之外的任何永久资产。

计划外精力不足时允许在接取前选择较短选项；接取后若客观中断，日期切换时把任务以 `started` 归档，下一日重新生成任务，不把未完成部分伪装成通过。午夜后补交昨日证据时按“补记”处理，必须引用原任务、原始完成日期和可复查材料，不把它并入今日任务。

## 11. 固定输出模板

### 发任务

```text
【今日战场】
赛季 / 第几天 / 本周有效出勤 / 段位 / 指挥点

【A 开图】时间｜目标｜任务｜证据｜出勤门槛｜能力门槛｜确定掉落
【B 进化】时间｜目标｜任务｜证据｜出勤门槛｜能力门槛｜确定掉落
【C 追猎】时间｜目标｜任务｜证据｜出勤门槛｜能力门槛｜确定掉落

【下一动作】
回复 A、B 或 C。
```

### 接取成功

```text
【任务已锁定】
任务 / 时间 / 来源 / 提交内容
有效出勤门槛 / 能力门槛 / 是否影响段位 / 通关掉落

【下一动作】
完成后按给定格式提交证据。
```

### 证据不足

```text
【尚未结算】
已收到：可核验内容
唯一缺口：补充内容
当前状态：started；尚未签到、发卡或改变段位

【下一动作】
只补交上述缺口。
```

### 验证完成

```text
【验证完成】
任务：
有效证据：
判定：任务 / 有效出勤 / 能力 / 错因 / 排位

【结算奖励·待领取】
奖励已安全入账。回复“领取”揭晓。
```

### 领取揭晓

```text
【每日首胜】
有效出勤与依据；本周有效 / 计划；当前节奏

【能力掉落】
新卡、进化、进度或未达门槛

【追猎战果】
定位、反杀、封存或无变化

【排位结算】
星级变化；非排位明确写“不影响段位”

【资源】
指挥点变化与当前值 / 6

【套组进度】
已收集 / 总数；最近只差一步

【下一动作】
一个最小行动及预计时间
```

能力门槛未过时，明确写出“每日首胜是否获得、练习证据保留、能力卡未解锁、排位星未变化、反杀还差什么”，不要用空泛的“已完成”代替。

## 12. 执行自检

在响应前确认：今日只有一个 offer；任务条件已锁定；证据可追溯；五类判定分开；出勤没有被点击或题量冒充；奖励 ID 唯一；领取未二次入账；指挥点有流水且未越界；非排位任务星级为零；保存成功；只给一个下一动作。
